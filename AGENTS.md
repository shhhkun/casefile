## Code Comments and Documentation

Follow the existing codebase as the primary reference for comment style (detail, wording, and emphasis).

- Prefer concise `//` comments for normal implementation notes, reasoning, constraints, and non-obvious behavior.
- Use `/** */` / JSDoc when documenting a function, module, or exported API whose purpose, parameters, return behavior, or architectural significance benefits from formal documentation.
- Do not add comments that restate obvious code.
- Prefer explaining why something is done over describing what the code does.
- Keep comments concise and specific. Avoid verbose, tutorial-like comments.
- Do not add documentation solely because a function exists; use judgment based on whether the explanation provides useful context.
